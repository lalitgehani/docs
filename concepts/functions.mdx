**Functions** let tenants deploy real Python business logic on the SnackBase instance—HTTP-invocable, secret-aware, and dependency-capable—without a separate backend.

## Positioning

| Product | Role |
| --- | --- |
| Custom Endpoints | No-code HTTP action pipelines |
| Hooks / Workflows | Event/schedule/graph automation |
| Platform `@app.hook.*` | Trusted code shipped with the server |
| **Functions** | Tenant-deployed sandboxed Python FaaS |

## Invoke URL

```
POST /api/v1/f/{account_slug}/{function_slug}
```

Optional path suffix is supported: `/api/v1/f/{account_slug}/{slug}/sub/path`.

`auth_required` defaults to **true** (JWT / API key for the same account). Public webhooks set `auth_required=false`.

## Handler contract

```python
from snackbase_fn import Request, Response

def handler(req: Request) -> Response:
    return Response.json({"ok": True, "user": req.auth.user_id})
```

Async handlers are supported. Baseline packages in every env: `snackbase_fn` and `httpx`.

## Dependencies

Declare exact pins on deploy (`openai==1.66.0`). Unpinned names, ranges, and git/URL installs are rejected. The server runs **uv** at deploy time; invoke is offline (no PyPI on the hot path).

## Dual client

| Helper | Scope |
| --- | --- |
| `get_client()` | Caller-scoped token (respects collection rules) |
| `get_admin_client()` | Service token gated by function **grants** (deny-by-default) |

Encrypted collection fields stay redacted unless the function has both:

- grant `records.secrets.read:<collection>`
- API-key scope `records:secrets:read`

## Secrets

Function secrets are Fernet-encrypted, write-only on list, and injected as env vars into the child process. Names cannot start with `SNACKBASE_`.

## Isolation & limits

- Per-version venv + `python -I` subprocess
- Timeout kill (default 30s) → HTTP 504 / status `timeout`
- Per-account and global concurrency caps → 429
- SSRF egress policy: deny loopback, RFC1918, link-local, metadata, ports 25/587
- Nested invoke budget via `X-Function-Depth`

## Automation

Hooks, Workflows, and Custom Endpoints support action type `invoke_function`:

```json
{ "type": "invoke_function", "slug": "hello", "payload": { "x": 1 } }
```

## SDK & CLI

```ts
const { data } = await client.functions.invoke('hello', { body: { name: 'Ada' } });
```

```bash
snackbase functions list

snackbase functions logs hello

```

## Admin UI

Instance Admin → **Functions** (instance Admin only; not hosted in Cloud Console):

- **Code tab** — CodeMirror multi-file Python editor with line numbers, syntax highlighting, search, and folding. Switching files keeps each file’s content, cursor, selection, scroll position, and undo history.
- **File rules** — Relative POSIX paths only (for example `utils.py`, `lib/formatters.py`). Absolute paths, `..` segments, backslashes, empty names, and names longer than 255 characters are rejected in the UI and again on deploy.
- **Entrypoint** — Marked with ★. Use **Set as entrypoint** before removing the current entrypoint file. At least one source file is required.
- **Dependencies panel** — Exact pins (`package==version`) are the source of truth. The editor always generates a read-only `requirements.txt` from that list (including an empty file when there are no pins). Do not edit `requirements.txt` in the Code tab.
- **Deploy is save** — Source is persisted only when you deploy. A successful deploy creates an immutable Function version and clears the unsaved-changes indicator. Leaving or reloading with local edits prompts for confirmation; un-deployed edits exist only in the browser session and can be lost if you confirm leave.
- **Syntax preflight** — Deploy parses every `.py` / `.pyi` file before installing dependencies. Syntax errors return HTTP 400 with file, line, and column. Invalid imports still pass preflight; handler-contract checks remain on test/invoke.
- Also: test sheet, executions, versions/rollback, grants, and secrets.

There is no Python language-server / IntelliSense and no SQL query editor in this surface. The shared editor shell is language-adaptable for a future SQL Editor (dialect + collection schema completion) without replacing Function deploy or dirty-state behavior.
