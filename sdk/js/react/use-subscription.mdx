---
title: "useSubscription Hook"
description: "Realtime collection events in React"
---

`useSubscription` ensures the realtime connection is established, ref-counts shared collection subscriptions, and always invokes the latest callback.

## Import

```ts
import { useSubscription } from "@snackbase/react";
```

## Legacy form

```tsx
function LivePosts() {
  const [events, setEvents] = useState<any[]>([]);
  const { connected, error } = useSubscription("posts", "*", (data) => {
    setEvents((prev) => [...prev, data]);
  });

  return (
    <div>
      <span>{connected ? "Live" : "Offline"}</span>
      {error && <p>{error.message}</p>}
    </div>
  );
}
```

`event` may be `'create' | 'update' | 'delete' | '*'`.

## Multi-handler form

```tsx
function PostList() {
  const [posts, setPosts] = useState<any[]>([]);

  useSubscription("posts", ["create", "update", "delete"], {
    create: (post) => setPosts((prev) => [...prev, post]),
    update: (post) =>
      setPosts((prev) => prev.map((p) => (p.id === post.id ? post : p))),
    delete: (post) => setPosts((prev) => prev.filter((p) => p.id !== post.id)),
  });

  return (
    <ul>
      {posts.map((p) => (
        <li key={p.id}>{p.title}</li>
      ))}
    </ul>
  );
}
```

Handler keys are `create` / `update` / `delete` / `'*'` (not `onCreate`).

## Behavior

- Calls `realtime.connect()` when state is not already `connected` / `connecting`
- `connected` is true only when `getState() === 'connected'`
- Multiple components on the same collection share one SDK subscribe; unsubscribe runs when the last unmounts
- Callback identity changes do not resubscribe; the latest handlers always receive events

## Connection control

Use `useRealtime()` for explicit connect/disconnect and connection state UI:

```tsx
import { useRealtime } from "@snackbase/react";

function Status() {
  const { state, connect, disconnect } = useRealtime();
  return <span>{state}</span>;
}
```

## Merging events into list state

Prefer local state updates from subscription handlers (as above). Avoid putting event data into provider context so unrelated tree branches do not re-render on every message.
