## Overview

The SnackBase MCP server (`@snackbase/mcp`) exposes SnackBase's functionality as MCP tools that AI assistants can use. It provides a standardized interface for:

- **Data Operations**: Query, create, update, and delete records in any collection
- **User Management**: Manage users, groups, roles, and permissions
- **Account Management**: Handle multi-tenant accounts and their configurations
- **Automation**: Webhooks, hooks, custom endpoints, workflows, and background jobs
- **Admin Operations**: Access audit logs, email templates, macros, files, and more
- **Monitoring**: Retrieve dashboard statistics and migration status

## How It Works

The MCP server runs as a separate process that communicates via stdio (standard input/output). AI assistants that support MCP can:

1. Discover available tools through the MCP protocol
2. Call tools with appropriate parameters
3. Receive structured responses with data or errors

<Steps>
<Step title="AI Assistant sends a request">
The AI assistant (e.g., Claude Code) sends a tool call to the MCP server via stdio.
</Step>
<Step title="MCP Server processes the request">
The server authenticates using an API key, validates the request, and calls the appropriate SnackBase SDK service.
</Step>
<Step title="SnackBase API responds">
The SDK communicates with your SnackBase backend via REST API.
</Step>
<Step title="Result returned to AI">
The MCP server formats the response and returns it to the AI assistant, which can then use the information to help you.
</Step>
</Steps>

## Available Tools

The MCP server exposes **21** tools covering core and automation domains:

| Tool | Description |
|------|-------------|
| `snackbase_collections` | Manage collections (schemas) and their structure |
| `snackbase_records` | CRUD, batch, and aggregate on collection records |
| `snackbase_collection_rules` | Configure access control rules for collections |
| `snackbase_users` | User management (create requires `role_id`) |
| `snackbase_groups` | Group management for team-based access |
| `snackbase_roles` | Role-based access control |
| `snackbase_accounts` | Multi-tenant account management |
| `snackbase_invitations` | Admin invitations (list/create/resend/cancel) |
| `snackbase_api_keys` | API key create, list, get, revoke |
| `snackbase_admin` | Provider configurations and connection tests |
| `snackbase_dashboard` | Dashboard statistics (`range`: 7d/30d/90d) |
| `snackbase_audit_logs` | Audit log access and export |
| `snackbase_email_templates` | Email templates and send logs |
| `snackbase_macros` | SQL macro operations |
| `snackbase_migrations` | Migration status and history |
| `snackbase_webhooks` | Outbound collection webhooks and deliveries |
| `snackbase_hooks` | Event/schedule/manual hooks and executions |
| `snackbase_endpoints` | Custom HTTP endpoints and executions |
| `snackbase_workflows` | Workflow definitions and instance control |
| `snackbase_jobs` | Background job queue (**superadmin**) |
| `snackbase_files` | Download URL generation and file delete |

<Note>
**Not exposed:** interactive auth (password/OAuth/SAML/login/register), realtime WebSocket/SSE, `records.query` QueryBuilder, invitation public accept flows, and multipart file upload. Use `@snackbase/sdk` or the Admin UI for those surfaces. See [Tools Reference](/mcp/tools).
</Note>

## Security Model

The MCP server uses **API key authentication** exclusively (`SNACKBASE_URL` + `SNACKBASE_API_KEY`):

- **No user sessions or password login tools**
- Tools operate with the **permissions of the API key**
- Prefer dedicated service accounts with least privilege
- Superadmin keys can access jobs and system configuration across tenants — high blast radius
- Audit trail: MCP-driven mutations appear in audit logs when the backend records them

<Warning>
Never expose superadmin API keys to untrusted AI assistants. Always use the minimum required permissions for your use case. Store keys in MCP client env config, not in prompts or shared logs.
</Warning>
